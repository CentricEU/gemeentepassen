# Security Policy

## Supported versions

Only the latest release and the current `development` branch receive security fixes.

## Reporting a vulnerability

Please **do not** open a public GitHub issue for security vulnerabilities.

Instead, report vulnerabilities privately:

- Use GitHub's [private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) on this repository, **or**
- Email the maintainers at <!-- TODO: confirm security contact address --> info@gemeentepassen.eu

Please include a description of the issue, steps to reproduce, and the potential impact.

## What to expect

- Acknowledgement of your report within 5 working days
- An assessment and remediation plan for confirmed issues
- Credit in the release notes if desired (and if the report is valid)

## Scope notes

- Do not test against production environments or real citizen/supplier data.
- Secrets, credentials and personal data must never be included in reports or attachments.
